# Plan 9: harden git, then confine the implementer and the gate with nono

Goal: the implementer is the only agent that writes code and runs `Bash`, and it runs with the user's full privileges; the verify gate then runs the agent-written tests unconfined, and the factory's own git runs over a worktree the agent controls. Three steps: (G0) stop the factory's unconfined git from executing agent-planted config, (1) run the implementer under nono, (2) run the gate's tests under nono with its own minimal grants. Folded from the plan-reviewer's findings.

Honest scope: after this, **`project_subdir` is the only writable *project* path**, and **nono is the sole write barrier for Edit, Write and Bash** (under `acceptEdits` plus `--add-dir <worktree>` plus bare `Write`/`Edit` allow rules, claude's own rules likely allow writes anywhere in the worktree; cycle 0c measures this). nono's profile still grants `$TMPDIR`, `~/.claude`, `~/.claude.json` and Keychain files, and cycle 0 may add more.

## Decided (not up for review)
- uv, pytest, stdlib only. TDD, one red-green-commit per behaviour, failing test shown red first, never edit a passing test except those listed below. Never push. Nested `nono run` is denied inside an agent session, so the human runs every nono probe and the e2e; unit tests use the fake nono.
- Mechanism as plan 6: nono, cwd = `worktree/project_subdir`, `--read <resolved worktree>`, fail closed with no unconfined fallback. The implementer uses the `nolabs-ai/claude` profile (claude needs it to authenticate). Write scope for the project is `project_subdir` only (user's choice).
- **Keep `Bash(uv run pytest*)`** for the implementer (user's choice), with grants found by spike. **Stop-and-ask rule (replaces the old "narrow grants" rule):** any write grant to a location that an unconfined tool later reads (`~/.claude*`, a shared uv cache, a Python install, `$TMPDIR` content the factory reuses) means stop and bring it to the user. In particular, if cycle 0b shows agent-run code can write `~/.claude/` or `~/.claude.json` under the claude profile, Bash for the implementer is a persistent-code-execution path and the fallback (drop Bash from the implementer) is back on the table for the user to decide.
- **The gate does not use the claude profile.** It gets its own minimal grant set (worktree read, `project_subdir` write, a private per-task `UV_CACHE_DIR`, read of the Python install) found by the spike, because test code never needs `~/.claude` or the Keychain. The gate always sets `UV_LINK_MODE=copy` (hardlinks from a cache would bypass a read-only grant).
- The gate runs with the runner's filtered environment (`ANTHROPIC_API_KEY`, `VIRTUAL_ENV` and git variables stripped) plus the uv variables, not the full inherited environment.
- A gate timeout kills the whole process tree (shared with the runner's tree kill), not just the nono parent.

## Cycle G0 ($0, before any nono work): harden the factory's own git
The reviewer's finding (high plausibility, **unverified**): the agent can plant a nested repo under `project_subdir` (`target/x/.git/` or a `.git` file) whose config sets `core.fsmonitor=<cmd>`; `commit_all`'s `git add -A` records it as a gitlink and the next `git status --porcelain` starts git inside it, running the command unconfined. This exists today, independent of nono.
- G0.1 red probe as a test in a tmp repo: nested repo with `core.fsmonitor` writing a marker, `git add -A`, `git status --porcelain`; the marker exists today (red).
- G0.2 `run_git` (and the raw `subprocess.run(["git", ...])` calls in `gate.py`) prepend `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c diff.ignoreSubmodules=all`; status gets `--ignore-submodules=all`; diffs get `--no-ext-diff --no-textconv`. The marker is absent (green).
- G0.3 the gate refuses before `add -A`: any `.git` entry (file or directory) under `project_subdir`, or any mode-160000 entry, gives `GateResult(False, "nested_repo")` (filesystem walk, no git). Test both forms.
- G0.4 pin that no `.gitattributes` driver from the user's global config runs: a `.gitattributes` in `project_subdir` selecting a `diff`/`textconv`/`filter` driver defined in a test gitconfig does not run during audit diff or add.
- Stated, not fixed: `--no-verify` skips only pre-commit and commit-msg; the hooks directory is not agent-writable.

## Cycles (after G0 and cycle 0; exact flags, grants and settings fixed by the results)

Decide and test the missing-nono case for the implementer (today it is a `runner_error` that charges an assumed 2x budget although nothing ran).
C. **Gate confined** (`gate.py`, `verify_task.py`, `stages.py`): `check_gate(..., test_prefix=(), env=None)` runs `test_prefix + test_argv` through the runner's Popen with `start_new_session=True` and the shared tree kill, the filtered env plus `UV_CACHE_DIR` (private, per task) and `UV_LINK_MODE=copy`; `OSError` from a missing wrapper gives `GateResult(False, "sandbox_unavailable")`, never an unconfined run or an uncaught `FileNotFoundError`. Tests: fake wrapper logs argv and execs the rest; a forked grandchild is dead after a timeout; an env-var token is absent from the test process; fail closed.
D. **Call-site pins:** a test per wrapped call site (implement via runner, gate), and an explicit allow-list of unconfined subprocess commands (the hardened factory `git` set, `pgrep`); not a grep of `subprocess.run` counts.
E. **Throwaway e2e (human, real terminal).** The plan 6/8 flow with a goal that asks the implementer to add `power` and, in a test, try writing canaries at `$HOME`, the repo root and `~/.claude/<canary>`, reading the uv cache and an env token, and creating a nested repo with an fsmonitor marker. Check: no canary or marker file exists, tokens absent from `factory show`, and the task either reaches `audited` or fails for an understood reason.

## Residual exposure (accepted, subject to cycle 0)
- nono still grants `$TMPDIR`, `~/.claude` (r+w), `~/.claude.json` and Keychain files to the **implementer** (claude profile). If agent-run code can write there, that is persistence into the user's later unconfined sessions; cycle 0b decides whether this is acceptable or Bash is dropped.
- The implementer's environment is inherited minus the variables the runner strips; its Bash pytest can read the rest. Network is unrestricted, so anything readable can be exfiltrated (domain filtering is out of scope).
- The allow rule `Bash(uv run pytest*)` admits extra arguments and arbitrary agent-written test code.
- Tool-level read confinement still depends on claude's default rules (plan 6).
- Merged content that your unconfined tools interpret later (`.envrc`, `.vscode/`, `pyproject` index or sources changes) is checked only by the human reading the diffstat at `factory merge`.
- nono stderr stays discarded: a missing grant shows up only as a failed test run or a failed gate. Git hooks other than pre-commit and commit-msg are not disabled by `--no-verify` (the hooks directory is not agent-writable).

## Out of scope
Network egress rules, Linux support, capturing nono stderr, retry or merge changes, an `abandon` command, confining the planner's worktree creation, a private claude profile derived for the implementer.
