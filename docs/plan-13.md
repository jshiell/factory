# Plan 13: the gate runs only what is committed (clean the worktree before the tests)

Goal: close the gitignored-file bypass recorded in plans 9 and 12. An agent with Write can create `proj/.gitignore` listing `conftest.py` (or `test_zz.py`, `pytest.ini`) and then write that file. `commit_all` (`git add -A`) skips it, so no diff check sees it, but pytest runs in the worktree and loads it. After this plan, every file the gate's tests can see is a file the tamper checks saw.

## Decided (not up for review)
- uv, pytest, stdlib only. TDD, one red-green-commit per behaviour, failing test shown red first, never edit a passing test. Never push.
- **Mechanism:** in `_gate_once`, after `commit_all` and before `check_gate`, run `git clean -ffdx` from the worktree root through the hardened git helper (`run_git`). `-x` ignores all ignore rules, so ignored and untracked files, including `.venv` and caches, are removed; tracked files are untouched. `uv run` recreates `.venv` from the gate's private uv cache (so each gate run pays a venv rebuild; accepted).
- Whole worktree, not just the project subdir: pytest also loads `conftest.py` and config from directories above the project (inside the worktree).
- Runs before every gate run, so each fix round is covered. The nested-repo check stays first (it already walks ignored paths too).
- No change to the gate's checks, the sandbox, the fix loop or the state machine.

## Cycles
C1. **Clean helper.** `clean_untracked(worktree)` in `gate.py` (or `worktrees.py`): removes an ignored file, an untracked file, an ignored directory and a symlink (without following it, target untouched); leaves tracked files; never touches `.git`.
C2. **Wired in `_gate_once`.** Red test: a worktree where the implementer left `proj/.gitignore` (`conftest.py`) and an ignored `proj/conftest.py` that makes the tests fail or pass differently; after `verify_task` the conftest is gone and the gate result is computed without it (use a test_argv that checks for the file). The `.gitignore` itself is tracked and stays.
C3. **Every round.** A fix round that writes an ignored file is cleaned before the next gate run (test).
C4. **Tracked-but-changed is not cleaned:** a tracked test edit still reaches the tamper check (existing tests stay green).
E1. **Throwaway e2e (human, real terminal, $0):** `spike/clean_gate_e2e.py` on a synthetic git repo with the real `build_gate_sandbox` and a real `uv run pytest` project: an ignored `conftest.py` that forces the failing test to pass is removed and the gate fails as it should; a legitimate project (`uv run pytest`, `.venv` created by the first run) still passes, with the timing of the venv rebuild reported.

## Residual exposure
- A new test file can still monkeypatch the code under test at import time (plan 12 residual).
- Tracked files above the project subdir (a changed root `conftest.py`, root `pyproject.toml`) are unwatched by the tamper checks; this plan only removes the untracked path.
- A project whose tests legitimately need an ignored file (a local `.env`, generated fixtures) will now fail the gate; such files must be committed or generated by the tests.
- Each gate run rebuilds `.venv`; a slow install makes every fix round slower.
- `git clean` runs unconfined (trusted git, hardened config, nested repos already rejected).
- Not verified: git clean behaviour on a read-only ignored directory (it would fail; the gate should fail closed), and how long a real venv rebuild takes.

## Out of scope
Re-planning on a moved main, branch GC, watching tracked config above the project subdir, new-test quality checks.
